# Threat model and security boundaries

## M0 assets

Reference datasets, dataset checksums, validation rules, benchmark fixtures, provider responses,
and local database credentials.

## M1 and M2 pilot assets

Pilot API keys, request correlation hashes, redacted usage measurements, optional 90-day encrypted
shadow values, and operational credentials. Full values are retained only for the protected
operator monitor after explicit customer configuration.

## Controls

- PostgreSQL binds to the private host/network; only local development exposes it on `127.0.0.1`.
- Caddy is the only application ingress behind Cloudflare.
- API keys are returned once and stored only as one-way verifiers.
- API-key files are created only at an explicit operator-selected path with owner-only permissions.
- Usage events store a key-scoped HMAC bound to the operation and canonical request, never the
  plaintext idempotency key, raw validated values, request bodies, or API keys.
- Browser SDKs use an integrator-owned same-origin proxy. Pilot API keys are never embedded in
  client bundles, HTML, local storage, or form markup.
- The trusted proxy overwrites browser telemetry attribution with its configured client identity,
  rejects non-loopback plaintext upstreams, and applies a process-local safety ceiling. The host
  and Cloudflare still enforce per-source limits.
- Full monitor values use per-value AES-256-GCM encryption with a random nonce and associated data
  binding the ciphertext to its observation and field. The key stays outside PostgreSQL.
- The full-value endpoint requires the server-held operator credential and is reachable through the
Cloudflare Access-protected application. Rows are project-isolated, idempotent, expire after 90
  days, and never contain the complete request body. Observation storage remains fail-open.
- The form observer listens only for configured field changes. In `shadow` it never writes control
  values or renders validation UI. Assist is limited to configured e-mail and phone `suggest`
  modes after blur. E-mail `email.domain_typo` suggestions write only after **Opravit**.
  A valid Czech `phone.normalized` result is formatted automatically and immediately shows
  **Vrátit původní**; only that exact reversible case may write without the first click. Invalid or
  non-Czech phone responses render only a local warning. No assist path prevents submit or enables
  a blocking policy.
- The hosted script records `shown`, `applied`, `kept`, and `undone` against the concrete encrypted
  observation. The event carries only its Checkdrop request ID, while the protected operator join
  exposes the corresponding full e-mail or phone value. Interaction failures remain fail-open.
- Logs use field allow-lists and never include request bodies, raw PII, keys, sessions, or provider
  payloads.
- Request IDs are generated by Checkdrop, validation JSON is capped at 8 KiB before parsing, and
  API-key authentication plus validation have process-local request ceilings.
- Every external source has a timeout, bounded response handling, and explicit unavailable/stale
  evidence.
- Dataset activation is transactional and reversible.
- Production on one host requires encrypted off-host backups and a proven restore before pilot
  data is accepted.
- Strict/blocking policy cannot be activated during shadow or initial assist mode.
